# 实战经验

[English](lessons-learned.md)

每天让口袋 Bot 和多 agent 平台一起干活，攒下来的经验。都是通用做法，刻意不写机器名、地址、钥匙和单号。

## 1. 办公室分层：管家协调，员工干活

一台设备是一个办公室，里面的 agent 是员工。老板给目标，管家联络办公室、跟进，再汇总汇报。
这是[办公室模型](office-model.zh-CN.md)，不代表每台设备和每个助手都已接通。只验证过 Grok Bot + Multica；
webhook 叫醒实测中，Dots、Muse、Cue 和其他本地 agent 接入未测。

- **私人 Bot 是管家**：接你的需求、向对应办公室交办、跟进、回报，自己不干重活。
- **多 agent 平台是工作中枢**：负责派活给 agent，并沉淀结果、记录和经验。
- **验收和合并交给管家**，按你事先定好的规矩来。只有有风险的事（花钱、对外发布、删除、碰钥匙）才找人。

## 2. 推送接入的三个坑

- **Authorization 字段的值带上认证方式**：写成 `Bearer <token>`，不能只填 token。
- **静音时段按主人所在的时区设**，不要用服务器的时区；时段旁边写清时区。
- **每小时推送上限别设太低。** 设得太紧，忙的时候真事件会被拦下或拖到下一轮。叫醒迟到或被拦时，先查拦截原因；确认是正常事件触及上限后，再调整额度。

## 3. Bot 连续叫醒的上限

- **被拦下时要明确报错**：上限拦住一次叫醒，要给发送方一个清楚的错误，不能悄悄吞掉。
- **人发的消息不受限**：上限只管 Bot 和 agent 之间来回叫醒。
- **同一张单的唤醒要合并**：这张单已经在排队，就把新消息并进去，不要再排一次。
- **叫停一件事时，相关的要一起停**：取消一个任务，属于它的运行和后续动作也一起取消。

## 4. 换钥匙会让桌面端掉线

- **删钥匙前先确认谁在用**（桌面端、Bot、脚本），不要闭眼轮换把人踢下线。
- **钥匙失效要安全兜底**：自动把这个客户端标成离线，把它手上的活改派出去，并通知主人。

## 5. 每小时巡检

每小时跑一次小检查：现在谁在干活、有没有重复在跑、有没有卡住。小问题（重复运行、残留的锁）自动清理，只把需要拍板的报上来。

## 6. 留下项目记忆，为以后换设备做准备

员工干完，把有用的决定和经验留进项目记忆。塔罗、toB、自媒体、学校这些方向积累的知识，是 Kun 想保住的资产。

**自动备份到 Google 云盘进行中**：计划 Grok Bot 每 **2 天**、Multica 每 **7 天**一次，尚未验收通过。
换设备、换总经理以后接着做，是设计目标，完整恢复未验证。详见[记忆与备份状态](office-model.zh-CN.md#记忆与备份状态)。

## 7. 带图的结果做成手机网页

凡是带图片、图表或截图的结果，一律做成一个手机能打开的单页网页（或 PDF）交付，不要发一堆零散文件。主人是在手机上看结果的。
